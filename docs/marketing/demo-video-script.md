# デモ動画の台本(Loom、目安 2 分 30 秒)

Day 48 の成果物。**そのまま読み上げれば録れる**粒度で書いてあります。録画はユーザー操作が必要なので、ここでは構成・操作順・ナレーションだけを用意しました。

## 収録前の準備

- **ワークスペースは `Neorie Demo`(`/w/neorie-demo`)を使う。** デモ用データ(プロジェクト `churn-radar`、アイデア検証、プロダクト診断、LP、告知)が入っています
- ブラウザ幅は **1440px** 前後(README のスクリーンショットと同条件)。ブックマークバーは隠す
- OS 通知・Slack・メールをオフにする(録画に写り込むと撮り直しになります)
- ライトモードで録る。ダークモードは末尾で 1 度だけ切り替えて見せる
- **AI 実行の待ち時間(1〜2 分)は編集でカットする。** Loom なら「トリム」で詰める。カットする箇所は下記に明記しました

## 全体構成

| 時間      | 内容               | 画面                              |
| --------- | ------------------ | --------------------------------- |
| 0:00-0:15 | つかみ(何の課題か) | マーケティング LP                 |
| 0:15-0:35 | プロジェクトを作る | ワークスペース → 新規プロジェクト |
| 0:35-1:10 | アイデア検証       | 実行 →(カット)→ 結果              |
| 1:10-1:40 | プロダクト診断     | 実行 →(カット)→ 結果              |
| 1:40-2:05 | LP 生成と公開      | LP プレビュー / ブロックエディタ  |
| 2:05-2:25 | 告知配信           | X 文面 + ブログ記事               |
| 2:25-2:35 | 締め + CTA         | プロジェクト詳細                  |

---

## カット 1(0:00-0:15)つかみ

**画面**: `https://neorie.com` のトップ(未ログイン)をゆっくりスクロール。

> 個人開発って、作る以外の作業が全部バラバラになりがちです。アイデアのメモ、競合調査、README、リリース告知。Neorie は、そこを 1 か所にまとめて AI に手伝わせるサービスです。

## カット 2(0:15-0:35)プロジェクトを作る

**画面**: `/w/neorie-demo` → 「新規プロジェクト」→ 名前と概要が入った状態を見せる → 「詳細情報」アコーディオンを開く。

> まずプロジェクトを作ります。名前と概要だけでも始められますが、この「詳細情報」を埋めておくと、あとで出てくる AI の精度が上がります。想定ユーザー、解きたい課題、機能、課金モデル。ここが後の入力源になります。

**補足**: 実際に作成まで進めず、既存の `churn-radar` に切り替えて構いません(録画を短く保てます)。

## カット 3(0:35-1:10)アイデア検証

**画面**: プロジェクト詳細 →「アイデア検証」カード → 「検証を実行する」→ ダイアログ(クレジット表示を一瞬見せる)→ 実行。

> 最初に使うのがアイデア検証です。このアイデアが筋が良いのかを、AI が Web 検索で実際の競合を調べたうえで採点します。消費するクレジットは実行前に出ます。

**→ ここで実行待ちをカット。** 結果ページを開いた状態から再開。

> 結果です。総合スコアと、Go / Pivot / No-Go の判定。5 つの軸ごとに点数と、なぜその点数なのかの根拠が出ます。ここは Pivot。「差別化の方向は明確だけど、スコアリングのロジック自体の独自性が薄い」と指摘されています。作り始める前に、これを言ってもらえるのが大きいです。

**見せる場所**: 総合スコア → レーダーチャート → 軸の講評を 1 つだけ読む(全部読まない)。

## カット 4(1:10-1:40)プロダクト診断

**画面**: プロジェクトの状態を「開発中」にしてから、「プロダクト診断」カード → 実行。

> 開発が始まったら、今度はプロダクト診断です。同じように競合を調べて、今のプロダクトのレベルを 5 軸でスコア化します。

**→ 実行待ちをカット。**

> 競合を実名で挙げたうえで、「この価格帯で似たポジションを取られている」「README や LP が無いので訴求が外に伝わっていない」といった指摘が出ます。改善提案もそのまま出ます。

## カット 5(1:40-2:05)LP 生成と公開

**画面**: 「ランディングページ」→ AI で生成 →(カット)→ プレビュー → 「編集」でブロックエディタ。

> 訴求が足りないと言われたので、ランディングページを作ります。AI がヒーロー・機能紹介・CTA といったブロック構造で生成します。

> ブロックごとにテキストを直せて、カラーテーマも選べます。公開すると、そのまま公開 URL で配信できます。

**注意**: 「公開する」は押しても構いませんが、押す場合は**デモ用プロジェクトであること**を確認してください(公開 URL が実際に外部から見えます)。

## カット 6(2:05-2:25)告知配信

**画面**: 「告知」→ 告知を作成 → AI で文面を生成 →(カット)→ X とブログの 2 カードを見せる。

> 最後がリリース告知です。伝えたいことを 1 回書くと、X 用の投稿文とブログ記事を同時に作ります。X は文字数もカウントされていて、そのまま投稿画面へ渡せます。ブログはこのまま公開 URL を持てます。

**注意**: 「X で投稿する」は**押さない**でください(実際の投稿画面が開きます)。

## カット 7(2:25-2:35)締め

**画面**: プロジェクト詳細に戻り、右上のテーマ切替でダークモードにして終わる。

> アイデアの検証から、診断、LP、告知まで。個人開発の「作る以外」を 1 か所に置いておけます。7 日間、カード登録なしで試せます。

## 撮影上の注意

- **実績・利用者数・導入事例を口頭でも言わない。** 実ユーザーがいない段階なので、事実でない訴求は避けます
- 画面に**他プロジェクトの実データ**が写らないよう、`Neorie Demo` ワークスペースから出ない
- 課金画面(Stripe Customer Portal)は今回のデモに**入れない**。決済情報が写るリスクがあるためです
- 撮り直す場合はカット単位で。全部通しで撮ると必ずどこかで噛みます
